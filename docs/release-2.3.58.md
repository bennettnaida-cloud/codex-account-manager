# 2.3.58（本地 Windows 构建）

修复删除账号后重新添加相同邮箱或复用相同凭据目录时，旧额度与用量重新显示的问题。基于 2.3.57，保留 CPA fill-first、10%/3% 保留线、失败冷却与长请求行为。

- 新增账号和文件导入均创建独立注册标识与注册时间；再次添加同名、同目录账号也不会复用旧额度、监测估算或网关故障状态。既有账号升级不会改变原身份；修改名称保留原账号数据。
- 用量汇总中，明确属于旧标识的数据不再回退匹配同名新账号。没有标识的旧版记录只有在新账号注册后的有效切换边界内才可归属新账号，避免删除前的切换记录继续影响新增账号。
- 删除入口统一清理该账号的官方额度快照、额度监测状态与网关额度耗尽记录；延迟返回的旧额度结果即使再次写入，也只能属于旧账号标识。
- 后台报表及账号显示快照保留注册身份；已删除账号的异步登录状态不回填到新同名条目。过期列表对象不能删除同名的新注册账号。
- 网关能力升级至 v18，继续兼容读取旧 v17 状态；新注册账号必须由认识注册标识的新网关转发，避免旧后台使用旧账号键。
- 共享聊天文件和历史用量账本保留。旧账号的历史用量不转嫁给新账号，按既有未分配历史口径保留；其他账号的数据不受影响。

本地删除不会重置服务端额度。重新登录或导入同一个官方账号后，刷新得到的余额和重置时间仍以服务端实际返回为准。升级不会猜测或清空所有现存账号历史；从此版本执行的删除重加流程获得完整生命周期隔离。

验证覆盖：旧版身份兼容、同邮箱同目录删除重加、延迟额度写入、缓存清理范围、改名与重新读取、删除后文件重导入，以及冷缓存/热缓存/重新创建统计器时的自然日志、探针账本和中转导入账单隔离。轮换回归继续验证主备池、保留线和 CPA 调度。

未上传 GitHub，未重启 Codex、管理器或网关。运行中的旧进程不会因构建新包自动更新；本地快捷方式指向 2.3.58 后，用户可在方便时自行重开管理器。
