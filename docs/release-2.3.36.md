# Windows 2.3.36：启动等待与本地补丁发布

## 修复范围

- 普通“Codex 启动”和“语音/手机”共享一次经过认证的本地网关准备，移除 UI 和本地 PAT 校验的重复检查。启动校验不会重启正在使用的网关，也不会发送 PAT 登录、模型推理或额度探测请求。
- 网关启动锁最多等待 8 秒；桌面网关准备使用整体 12 秒取消预算。取消/超时发生在关闭旧客户端和投放共享凭据之前，并给出明确错误。取消不会释放其他操作持有的锁，也不会在取消后启动网关。
- 原生节点启动的端口等待改用带取消的 TCP 连接。原来只有外层 4 秒循环限制，单次同步 Connect 仍可能超时更久；现在连接本身与重试共享同一个期限。
- 本地凭据校验和共享配置匹配在工作线程执行，避免慢磁盘阻塞启动进度。启动期间维持忙状态、秒数和阶段提示；连续点击不排队。
- 启动前历史维护采用 8MiB 工作量预算，包含大文件序号修复的扫描、备份与暂存成本。超出预算的序号重写保留原文件，留给原有离线维护路径；不删除聊天记录，不声称这是磁盘 I/O 的硬性时间上限。
- 同账号复用窗口跳过重复插件扫描。诊断记录轮换清理、网关准备、本地校验、兼容 API 预检、旧进程退出、历史维护、插件检查、系统激活、首次窗口可见与主页面就绪，使用统一 launch-id，不记录凭据。
- 可选日志目录枚举与基线采样限制为各 1 秒/4096 个文件的协作式工作预算。超额、损坏或无法读取时废弃整个基线，不把旧日志当作本次就绪证据，也不阻止系统激活；这不是对 Windows 底层磁盘调用的硬性超时保证。

## 一并发布之前的本地修复

- 通过可信 Codex 进程身份和原生窗口枚举发现隐藏的 Electron 主窗口，不把已运行数小时但没有 MainWindowHandle 的客户端当作“仍在初始化”。已有窗口直接显示/还原；无法唯一确定窗口时使用官方空参数激活，不重新投递新聊天，不整页刷新。
- 后台观察结束时释放对应的“正在初始化”身份，不影响后续启动。保留进程退出、检测不可用与初始化未完成的区别，不因就绪检测超时关闭健康客户端。
- 新账号配置默认显示 low、medium、high、xhigh、max、ultra 六档，另保留原生 persistent 模式。共享桌面偏好随模型凭据投放保留；已有自定义子集、空数组和默认模型不被覆盖。选项显示不等于所有模型支持每一档强度。
- 保留 2.3.35 的账号模型自动发现、逐账号代理、双登录功能身份、轮换、快捷方式更新和共享聊天记录。

## 证据与验证边界

GitHub 2.3.35 的源码不包含上述隐藏窗口和六档推理本地补丁。本机 2026-10-09 的既有诊断显示系统激活约 3 秒、主页面就绪约 29 秒，不能将后台就绪观察误写成窗口一直没有显示。

朋友电脑仅确认使用 GitHub 2.3.35，未提供启动阶段和日志。因此十分钟的具体原因尚未在该电脑复现；重复网关准备、无界锁等待、界面线程磁盘操作及大文件历史维护是本次代码审计确认并收敛的风险点，不能承诺网络、官方更新下载或磁盘异常下的固定启动时长。

发布前执行 Release 构建、完整 self-test、startup-self-test、真实隔离 app-server 模型目录回归、快捷方式回归及一键安装包隐私/隔离安装检查。专项自检覆盖网关重复准备、锁竞争、超时/取消、不接管外来监听器、隐藏窗口身份、并发与过期导航；不在当前正在服务的 Codex 上执行关闭/重新登录测试，也不声称其他电脑已实测。
