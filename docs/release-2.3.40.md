# Windows 2.3.40 — 轮换额度保留线

开启账号轮换后，依据最新官方额度快照，在模型请求发送前应用以下规则：

- 存在 5 小时额度窗口：剩余 ≤10% 暂停该账号。
- 没有 5 小时窗口、只有周额度窗口：剩余 ≤3% 暂停该账号。
- 按窗口时长识别类型，支持 primary/secondary 顺序颠倒。兼容 API 不应用官方额度保留线。

触线账号不会作为后续轮换候选；普通会话粘性同样遵守保留线。保持使用池优先、备用池兜底的现有顺序。全部候选不可用时返回明确的 503，不继续消耗触线账号。暂停不等于禁用账号，也不伪造上游 429 耗尽证据；窗口重置或新的官方快照显示额度恢复后重新可选。已有耗尽冷却仍遵守原有重置保护期。

已经发送的请求继续完成；只有候选响应完整成功才提交全局轮换和普通会话绑定。携带 previous_response_id 的严格续聊不能跨账号迁移，触线时返回 409，需等待恢复或新建会话。

轮换页显示两条保留线、周额度和暂停状态。网关 healthz 的 quotaReserve 字段可核实运行版本采用的保留值。

限制：按最新已查询到的官方额度判断，不预测在途请求的消耗，不能保证实际余额精确停在 10% / 3%。未知额度不推断为 0%，继续保留上游限额处理。此变更针对 Windows 管理器；macOS 未移植这套轮换功能。

验证：策略边界、5h 优先级、周额度、缺失重置时间及恢复测试；本地 HTTP 网关测试覆盖提前跳过、备用池、全部暂停、严格续聊拒绝、失败不提交及会话绑定；完整应用自测。
