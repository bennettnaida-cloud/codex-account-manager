# 2.3.39：账号模型发现与桌面启动闭环

## 已确认的缺口

- 2.3.38 普通“Codex 启动”和“语音 / 手机”入口使用 `localOnly` 验证，因而跳过 AT 在线目录准备。首次启动可能在后台刷新完成前读入旧目录；之后写入文件并不代表已有 app-server 已重新加载。
- AT 的短期目录收据记录了 CLI 版本，但没有用它决定是否可复用缓存。桌面更新后可能继续沿用旧客户端条件下查询的结果。
- 兼容 API `/models` 返回空、坏数据或没有可用于 Codex 的模型时，部分刷新调用直接返回，被视为正常完成。
- 官网价格检查与账号模型发现是不同功能，但原界面只有价格检查按钮，没有逐账号模型同步结果。

这些是源码与回归可以确认的缺口；没有朋友电脑的诊断数据，不能宣称它们就是那台电脑的唯一原因。

## 修复

- 两个 Windows 桌面入口在关闭旧客户端、修改共享凭据之前，准备当前 AT 的模型目录。只查询元数据，不运行模型生成、登录医生或额度测试；总等待有取消上限，仍使用当前账号自己的凭据和节点。
- 客户端版本变化后重新查询。网络临时失败只沿用同一凭据已验证的目录，并在启动结果中提示旧目录；401 不作离线回退。桌面默认模型或档位不在目录中时明确提示，仍允许进入 Codex 选择该账号的其他可用模型，不把一个默认项错误升级成整个账号无法启动。
- 同步失败保留上一份目录，API 空、坏、过大及不支持的响应不再报告为成功。账号地址、凭据变化时丢弃过期结果。
- Windows 系统配置新增“同步账号可用模型”，独立于价格设置，逐账号报告目录数量、失败原因及自定义目录阻挡。后台结果可见，不自动重启 Codex。
- 下一次明确点击启动同账号时，仅在其目录文件确实晚于当前可信桌面进程启动时间时重载，避免继续复用持有旧目录的 app-server；目录未改变时仍复用窗口。目录指针投放与切号共用互斥，避免后台同步越过正在进行的账号切换。
- 只有顶层自定义 `model_catalog_json` 阻止默认投放，旧的未激活 profile 不再被误判为全局覆盖。真正的用户自定义目录仍保留。
- Windows/macOS 内置官方 CLI 更新到 `0.163.0`。Mac 短期缓存也校验客户端版本，发布仍保留原生安装、签名及渲染冒烟检查。

## 验证口径

测试使用隔离目录、伪造凭据和本机 HTTP fixture，不改用户账号或聊天，不关闭运行中的管理器/网关。覆盖远端新模型、未来模型 ID、完整元数据与隐藏字段、版本升级缓存失效、失败保留旧目录、过期身份、分页和真实 CLI `model/list` 消费。安装包执行隐私检查。macOS 的真实安装与消费检查由 Apple Silicon GitHub runner 执行。

模型目录不等于无条件授权：只有该账号在 Codex 或对应上游可用的模型才能实际使用；Work 中出现的模型不能直接代替 Codex 授权证据。已打开的 Codex 可能需用户自行完全退出、重新启动加载新目录。未来如果服务端协议或客户端能力不兼容，仍可能需要适配，不能保证永久无需更新。

实现参考：[OpenAI Docs：Codex App Server model/list](https://learn.chatgpt.com/docs/app-server#models)，要求按当前客户端与账号返回的模型和能力显示，而不是固定版本列表。
