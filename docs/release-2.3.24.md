# 2.3.24：语音/手机加载页与桌面启动网络

## 根因和变更

26.924.2738.0 的白色标志窗口只是渲染器启动。登录、功能开关和插件初始化尚未完成时也会出现该窗口。失败日志中可见官方网络策略尚在加载、配置读取被插件操作排队，以及登录后功能初始化请求超时；没有证据表明这次停留由目录栏冲突或 Page.reload 引起。

1. 原来账号固定节点只覆盖模型网关，Chromium 的登录与功能请求仍继承系统出口。普通 Codex 和语音/手机冷启动现在均显式传递所选账号代理，启动所需节点在关闭旧客户端前解析。模型请求仍由网关按实际账号路由，OAuth 功能身份不变；不修改 Windows 系统代理。回环地址绕过代理。代理失效按既有账号回退策略处理；含认证凭据的远程代理不能作为可见启动参数，需使用本地入口或原生节点。
2. 投放账号模板不再丢弃共享桌面的插件和 marketplace 状态。双登录允许官方原生插件初始化，避免旧的全局禁用开关造成重复安装；保留已有插件单独禁用值和 Sites 专项安全排除。不复制旧模型 provider/bearer，不触碰聊天记录。
3. 点击锁和阶段进度持续到本次 PID 的主页面就绪。进程退出、初始化错误、未确认就绪各有反馈，不因日志不可用或慢初始化强制重启。可选 Fast 仍不强制刷新页面。

## 验证

- Release 构建与完整 `--self-test` 通过；`--startup-self-test` 通过，覆盖两个入口参数、账号切换/窗口复用决策、连续点击、过期导航、外置 app-server、日志缺失/慢就绪、可选补丁降级、插件状态及凭据隔离。
- 在独立 CODEX_HOME、数据库和 Electron 用户目录运行已安装的官方 26.924.2738.0；不关闭用户的工作窗口或网关。复制的测试凭据不写回真实账号。
- 已预热官方插件的配置：日本节点同时用于桌面与子进程时，主路由 8,490 ms 就绪；只改变桌面代理、子进程仍继承美国节点时，7,513 ms 就绪。原全局出口对照约 43 秒且有登录后功能初始化超时。这是多次具体观测，不是性能保证或严格单因素基准。
- 全新隔离配置、日本桌面节点：主路由 19,484 ms 就绪，首次安装五个官方原生插件。仍观察到官方网络策略加载期间的短暂拒绝，随后自行恢复；没有通过关闭策略、修改官方资源或刷新页面规避。
- RPC 只读验证：getAuthStatus 返回的身份与 OAuth 凭据一致，非兼容 API 模型密钥。
- 桌面和任务栏快捷方式同步测试通过。其他电脑、所有节点、实际语音通话/手机配对、Dream Skin 自定义启动未实测。当前会话工作窗口未用于破坏性的切号验收。

## 安装

版本 2.3.24，网关端口 8341，独立目录安装。当前运行中的 2.3.23/8340 可继续工作；关闭旧管理器后从已更新的桌面或任务栏入口启动新版，再主动启动 Codex，才会使用新流程。不会自动关闭本次工作的网关。
