# Windows 2.3.38：修复 AT 模型刷新读回旧目录

## 根因

2.3.37 将账号模型写入 `model_catalog_json`，随后在同一账号配置下运行 `codex debug models`。CLI 此时可以直接返回静态目录，不查询服务器；即使命令退出成功，也不能证明在线刷新成功。旧 `models_cache.json` 的回退同样没有验证更新时间和账号身份。

## 修改

- AT 模型发现独立于静态 TOML、CLI 内置目录及当前会话轮换。只使用该 AT 的凭据，通过其绑定代理，先查询工作区身份，再请求官方 Codex 模型目录。
- 使用实际已安装 CLI 的版本，不硬编码未来模型 ID、不修改服务器的可见性或能力字段。保留完整模型元数据及用户选中的默认模型。
- 成功后记录凭据指纹、目录内容哈希、客户端版本和查询时间；启动可复用 15 分钟内的已验证目录。需要的模型不在旧目录时重新在线查询，不提前判定未授权。
- 失败保留上一份目录，后台/手动刷新明确计入失败。启动遇到临时网络故障时仅可沿用同一凭据已验证且支持默认模型的目录；认证失败不作此回退。
- 同账号串行刷新。请求期间删除账号或更换凭据会丢弃旧结果；请求可取消，响应长度及耗时有限制，日志不包含密钥和响应正文。
- 保留手动 `model_catalog_json`。不会关闭管理器、网关或 Codex；已打开的 Codex 可能需要用户自行重启才能显示新增模型。

## 验证

- 自动回归：旧静态目录与缓存存在时仍执行远端请求；未来模型和额外元数据保存；工作区绑定；401、503、空/坏/过大响应及取消保留目录；凭据变化拒绝旧结果；离线启动与不支持的默认模型处理。
- 本机真实 AT 查询：收到 9 条记录，7 个可选模型，包含 `gpt-6.1-sol`。使用本机 CLI `0.162.0-alpha.17.2` 的隔离 app-server 验证 `model/list` 能列出 7 个可选模型。没有发送生成请求、重启用户客户端或修改登录凭据。
- 发布流程仍执行完整自检、Windows 启动回归、兼容 API 模型回归、安装包与隐私检查，并校验源码、程序和更新清单的版本。

## 边界

朋友电脑没有日志，未在那里实测。Work 和 Codex 的模型列表不能互相作为授权证明；以该账号的 Codex 返回和客户端兼容性为准。此次修复不绕过官网价格页的 HTTP 403，不改变价格更新功能，也不保证未来服务端协议变化无需适配。

实现依据：[Codex 模型调试命令](https://learn.chatgpt.com/docs/developer-commands#codex-debug-models)、[官方 models 查询实现](https://github.com/openai/codex/blob/rust-v0.154.0/codex-rs/codex-api/src/endpoint/models.rs)。
